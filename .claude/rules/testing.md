# 測試紀律

本 Rule 涵蓋所有測試工作，不限於特定流程。

## 測試前

1. 先讀既有測試，沿用測試位置、命名、helper 與隔離方式，不另起一套慣例。
2. 指名這次要驗證的行為與對應的測試檔案、案例名稱。不確定時標記「未確認」，不捏造對應關係。
3. 使用專案的正式測試命令；臨時拼湊的命令只能用於本地探索，不作為驗證依據。

## 撰寫測試

1. 新測試必須被正式測試命令收錄並實際執行——寫了但沒被跑到的測試等於不存在。
2. 外部相依（網路、第三方服務、時鐘、檔案系統）以 mock、fake 或可控測試替身隔離。
3. 避免時間、隨機、排序、網路與共享狀態造成的脆弱測試；需要固定值時明確注入，不依賴執行環境。
4. Unit test 不跨越持久化、網路或真實第三方服務邊界；需要跨界時改寫成 integration test 並標明。

## 回報結果

1. 驗證欄必須指名測試檔與可觀察判準，不只寫「測試通過」。
2. 完整 suite 只保留統計及失敗／跳過案例，不展開未變更的成功案例。
3. 無法執行的驗證明確標示為未執行，不能寫成已通過。
4. 不把 raw stdout/stderr、環境變數或機密寫進回報；失敗摘要只使用已遮蔽、已截斷的內容。
